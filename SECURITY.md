# Security model

This educational offline simulator accepts invented JSON scenarios and emits reports. It provides no real retry authorization, endpoint protection, authentication, storage transaction, exactly-once guarantee or evidence of actual business effects. Caller/operation/intent labels and input hashes are supplied assertions, not trusted identities or signatures.

Threats considered: duplicate or ambiguous fields/IDs, bool-as-integer, malformed late actions, invalid completion references/cuts, optimistic outcome inference, excessive input/counter/report expansion, markup/control injection, output clobbering and partial publication. Strict bounded decoding, exact fields, full semantic validation before rendering, scoped payload records and separate client/oracle views address these within the declared model. No input-derived code, network calls, persistence, shell commands or credentials are used.

Use synthetic data, trusted Python/source and trusted local regular files/directories. The CLI intentionally reads a supplied input and writes a supplied new report; it is not a sandbox for special devices, symlinks or hostile filesystem races. It reads at most the input cap plus one byte, but device blocking and process-memory limits are not enforced. Resource caps reject rather than truncate; output strings are escaped. Generic OS diagnostics omit file paths/details. Argparse usage concerns operator-supplied CLI arguments, not secret-safe logging.

New report publication uses an exclusive hard link after flushing; unsupported filesystems fail with no overwrite fallback. Hostile directory mutation, process/power loss, storage durability, malicious local administrators and private-data handling are outside the lab. A cleanup failure can leave a temporary file; exit 3 means a complete output was already published. Stdout failure can leave partial bytes. Inspect explicit exit diagnostics and actual files.

Pending/indeterminate records have no recovery protocol and never age out. Completed retention is not an owner lease. Atomicity is a pure-state assumption; this code must not be used as production deduplication middleware. Changes adding persistence, real operations, network traffic or deployment require a new plan and authorization. Publish only sanitized invented fixtures if publication is later approved.

Review: ECC self-review and local Bandit checks are recorded in ECC_REVIEW.md and VERIFICATION.md; they are not comprehensive or independent security assurance. The separate private repository has SHA-pinned, minimum-permission workflows and update configuration. Actions remains disabled pending usage/CodeQL licensing verification. No package installation, paid security activation or hosting was performed by this task. Local STATE/private material/evidence runs are excluded from commits.
